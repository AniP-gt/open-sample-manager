# mcp-audio-auto-tagging - Work Plan

## TL;DR (For humans)
**What you'll get:** The existing local MCP gains read-only preview and explicit apply operations that classify samples as loop or one-shot and assign instrument types such as Kick, Bass, and Tom. Results include confidence and reasons, uncertain Kick/Tom cases are withheld, and a missing Tom type is created safely only when an eligible result is applied.

**Why this approach:** Filename clues remain useful but cannot decide alone, so they are combined with acoustic measurements and a local ONNX model. Independent ownership and provenance protect manual edits, while versioned thresholds and reproducible benchmarks turn "accurate" into a measurable release gate.

**What it will NOT do:** It will not upload audio, use cloud inference, accept arbitrary tag names or model controls from MCP, silently overwrite manual or legacy classifications, or mutate the database during preview. It will not claim Windows or Linux support without actual packaged-model test evidence.

**Effort:** XL
**Risk:** High - the cross-platform code is straightforward relative to collecting licensed representative data and meeting calibrated Kick/Tom accuracy and coverage gates.
**Decisions to sanity-check:** Existing classifications are protected unless an apply request explicitly opts into replacing legacy ownership; the model uses one Tom family label while retaining subtype evidence; quality thresholds can reject release rather than silently weaken precision.

## Scope
### Must have
- Preserve the current `Node stdio MCP -> bearer-authenticated 127.0.0.1 API -> Rust SampleManager -> SQLite` topology.
- Add a Rust-owned classifier with two semantic heads: playback (`loop`, `oneshot`) and instrument (`kick`, `snare`, `hihat`, `tom`, `bass`, `synth`, `fx`, `vocal`, `percussion`, `other`).
- Fuse filename priors, deterministic DSP features, and a bundled ONNX model; filename evidence alone must never make a result apply-eligible.
- Treat Kick-vs-Tom as a dedicated confusion-risk slice using F0/glide, attack/decay, spectral centroid/bandwidth, harmonic/modal energy, and low/mid/high band ratios.
- Calibrate independent per-head/per-class thresholds and abstain on low confidence, insufficient margin, conflicting evidence, unsupported labels, model failure, stale content hashes, or protected ownership.
- Store per-field ownership (`legacy`, `manual`, `automatic`), confidence, model SHA-256, policy version, evidence summary, source content hash, fingerprint, and classified timestamp.
- Keep legacy canonical labels protected by default. `apply_auto_tags` may replace `legacy` ownership only when the caller explicitly sends `legacy_mode: "replace"`; it can never replace `manual` ownership. New scan/import rows are recorded as `legacy` with policy `legacy-heuristic-v1`; rescans preserve existing canonical labels and ownership.
- Make preview logically and physically read-only. Make apply per-sample transactional, idempotent, content-hash-aware, and retry-safe.
- Reconcile only canonical lowercase `tom` from a closed Rust allowlist during eligible apply; preview only reports `would_create_instrument_type`.
- Bundle a versioned ONNX model, model manifest, policy artifact, license/attribution metadata, and integrity hashes as Tauri resources.
- Provide deterministic training/export and benchmark tooling with pinned dependencies, immutable dataset manifests, leakage-safe file-level splits, and JSON evidence.
- Meet checked-in quality gates before enabling apply: the 95% Wilson upper bound for accepted-set Kick<->Tom confusion is `<2%`; micro precision `>=95%`; loop/oneshot and instrument macro-F1 `>=0.90`/`>=0.85`; 20-bin ECE `<=0.05` per head; coverage `>=60%`; Kick/Tom coverage `>=50%`. Thresholds use development only. The consumed test seal must contain at least 400 Kick and 400 Tom examples before abstention, with each class spanning at least 100 distinct source groups.

### Must NOT have (guardrails, anti-slop, scope boundaries)
- No cloud inference, audio upload, telemetry, remote MCP transport, second local API, or Python runtime sidecar.
- No arbitrary file paths, model paths, labels, taxonomy names, confidence thresholds, or SQL-like values accepted from MCP.
- No automatic write from filename evidence alone, no low-confidence fallback to legacy heuristics, and no mutation during preview.
- No overwrite of `manual` ownership, no silent overwrite of `legacy` ownership, and no case-variant taxonomy values such as `Tom` beside `tom`.
- No dynamic creation of labels outside the closed model taxonomy; this feature may auto-create only missing canonical `tom`.
- No raw logits, bearer tokens, model filesystem paths, or unbounded evidence blobs in API errors/responses.
- License policy is literal and fail-closed. Training may use only project-owned audio with a machine-verified grant, CC0-1.0, CC-BY-3.0, or CC-BY-4.0; reject NC, ND, SA, unknown/custom/revoked terms and commercial/model-training warnings. A project grant record must contain `grant_id`, grantor legal name, grantee `Open Sample Manager contributors`, exact asset IDs/SHA-256, rights booleans for training/modification/commercial use/redistribution of derived weights, worldwide territory, perpetual term, signed timestamp, signature or detached-document SHA-256, and evidence path; every right must be true and proof resolvable. Downloaded audio is local/gitignored/checksummed/never redistributed. Checked-in audible fixtures are project-owned-with-grant or CC0 only. Every asset manifest row requires title, creator, source URL, SPDX license, license URL, asset SHA-256, and source-group key. Generated `THIRD_PARTY_NOTICES.md` must include one attribution row per CC-BY asset plus dataset summary, title, creator, source, SPDX/license link, and modification statement `resampled, segmented, feature-extracted, and used to train derived model weights`; CC0/project-owned rows remain in the machine manifest. Derived weights ship under project license only if `verify-licenses --policy license-policy-v1` proves allowlist, grant rights, attribution completeness, and notices; otherwise export/package blocks pending explicit owner/legal decision.
- No UI redesign, unrelated search/tag refactor, or broad migration of existing classification UI.
- No claim of Windows/Linux support until target build and model-load smoke evidence exists.

- Benchmark JSON is a release gate, not a self-reported metric. It must include model SHA, policy SHA, dataset-manifest SHA, split seed, preprocessing version, OS/arch, command, per-class counts, confusion matrices, coverage/selective-risk curves, latency, and peak memory.
- Dataset qualification is a hard gate before training: exact asset IDs, SHA-256 values, source groups, licenses, mappings, and immutable train/dev/test assignments are sealed and hashed first. After sealing, training and threshold selection may read train/dev assets and dev predictions only; test assets/predictions remain access-blocked. Then freeze model and policy bytes/hashes and evaluate the unchanged sealed test exactly once. Any split/model/policy change invalidates that evaluation and requires a new explicitly versioned seal before another cycle.
- Model contract literals: 16 kHz mono; 4-second start/middle/end windows; exact STFT/mel/log frames; inputs float32 `log_mel [N,1,64,400]` and `handcrafted [N,24]`; outputs float32 playback `[N,2]` and instrument `[N,10]`. Convert each ONNX logit to f64, sum in canonical window order start then middle then end, divide by integer `N`, and pass the mean raw logits directly to the fusion equation below. Do not softmax before fusion; the fusion step performs the only softmax.
- Handcrafted feature order is fixed: log-duration, periodicity, onset density, boundary similarity, RMS mean/std, attack milliseconds, decay-T60 milliseconds, 20-120/120-400/400-2000/2000-8000 Hz energy ratios, centroid mean/std, bandwidth mean/std, spectral-flux mean, flatness mean, harmonic ratio, F0 voiced fraction, log-median F0, median F0 delta, p90 absolute F0 delta, and zero-crossing rate. Train-set mean/std scalers live in the hashed model manifest.
- Decode/preprocess formulas are fixed. Downmix each interleaved frame as the f64 arithmetic mean of channels with no clipping, then cast to f32. Pin `rubato = "=4.0.0"` with `default-features=false`; construct `SincFixedIn` with chunk 1024, `sinc_len=256`, `f_cutoff=Some(0.95)`, linear interpolation, oversampling 256, and `BlackmanHarris2`, then call rubato 4.0 `Resampler::process_all()` for the complete mono clip rather than manually processing chunks. `process_all()` must reset state, pad/drain zero input until at least `output_delay()+target_length` frames exist, discard exactly the delay, and return exactly target length `floor((input_frames*16000+input_rate/2)/input_rate)`; assert that length and never substitute right-padding for an undrained tail. Tests cover exact-multiple, one-short-of-chunk, one-over-chunk, input shorter than delay, and up/down non-unity rates. Training consumes tensors from this Rust CLI; independent golden DSP vectors use already-16-kHz fixtures. Window offsets, periodic Hann, DFT/power, HTK mel construction, and two floor frames remain exactly as stated.
- The 24 feature formulas are fixed and all refer to the complete resampled file, not an individual 4-second model window, except frame-local spectral/YIN computations that are aggregated over the complete file. `log_duration=ln(1+full_file_seconds)`; periodicity is existing full-file `BpmResult.periodicity_strength` clamped `[0,1]`; onset density counts full-file flux frames strictly greater than `mean+std` divided by full-file seconds; boundary similarity uses full-file first/last 250 ms mean log-mel; RMS uses 400/160 frames; attack/decay follow the next paragraph. Band bins are `[20,120)`, `[120,400)`, `[400,2000)`, `[2000,8000]`; ratios divide by total plus `1e-12`. Centroid/bandwidth use power weights and return zero on total power `<=1e-12`. Flux L1-normalizes each one-sided spectrum, maps silence to zero, and averages L2 positive differences. Flatness uses `exp(mean(ln(power+1e-12)))/(mean(power)+1e-12)` or zero for silence. For each voiced frame, harmonic centers are `floor(h*f0*512/16000+0.5)` for `h=1..8`; discard centers above bin 256, take the union of each center +/-1 clipped to `0..256` so overlaps count once, and divide union-bin power by total one-sided mapped-frame power plus `1e-12`; then aggregate per the next paragraph. YIN uses 640/160 frames and lag range `ceil(16000/2000)..floor(16000/40)`, first strict local minimum below 0.10 else unvoiced, with three-point interpolation only at interior lags.
- DSP alignment/tie rules are fixed. Frame timestamps use center sample `(start+(length-1)/2)/16000`; attack chooses earliest RMS >=10% of earliest peak RMS and the earliest peak, returns zero when threshold is at/after peak, and reports center distance. Decay's below-threshold condition is RMS `<=0.001*earliest_peak_RMS`; choose the earliest six consecutive qualifying frames after peak and measure peak-center to first-run-center; if absent use audio-end time, never negative. Boundary cosine is zero when either vector norm is zero. Map YIN to nearest spectral-frame center, earlier on tie. Harmonic ratio arithmetic-means voiced observations; duplicate mappings remain separate; no voiced frame is zero. F0 deltas require immediately adjacent voiced YIN frames; gaps break sequence; empty delta stats are zero. Percentiles use nearest-rank `ceil(p*n)-1`; ties preserve earliest index.
- Metric formulas are fixed. `accepted` means head status exactly `eligible`. For head `h`, `N_h` is all labeled/unmasked examples, `A_h` eligible decisions, `coverage_h=A_h/N_h`; overall coverage is `(A_playback+A_instrument)/(N_playback+N_instrument)`; micro precision is correct eligible axes divided by `A_playback+A_instrument`; Kick/Tom coverage is eligible truth-Kick/Tom decisions divided by all labeled/unmasked truth-Kick/Tom examples; zero denominators fail. `TP_c`, `FP_c`, `FN_c` include abstention as FN and `F1_c=2TP_c/(2TP_c+FP_c+FN_c)`; zero denominator fails; macro-F1 averages fixed classes. For Kick/Tom confusion, `x=eligible GT-kick predicted tom + eligible GT-tom predicted kick`, `n=all eligible truth-Kick/Tom`, `p=x/n`, and `n=0` fails; with `z=1.6448536269514722`, Wilson upper bound is `(p+z^2/(2n)+z*sqrt(p*(1-p)/n+z^2/(4n^2)))/(1+z^2/n)`; support requires >=400 examples and >=100 source groups per class before abstention, and replacement seals use unevaluated group-disjoint assets. ECE is per head over exactly `N_h` using calibrated/fused `final_probability` immediately before abstention: `confidence_i=max(final_probability_i)`, `correct_i=1` iff canonical-order `argmax==truth`. For `b=0..19`, lower=`b/20`, upper=`(b+1)/20`; bins 0..18 own `[lower,upper)`, bin 19 `[0.95,1.0]`; 0 enters first and 1 last; empty bins contribute 0. `ECE_h=sum_b (n_b/N_h)*abs((sum_correct_b/n_b)-(sum_confidence_b/n_b))`. Boundary fixtures cover `0,.05,.10,.95,1.0`, empty, masked, ties, and hand-calculated ECE.
- Fusion/calibration is fixed by hashed policy `algorithm_id="temperature_log_prior_v1"`. All averaging/fusion math is IEEE-754 f64 in canonical class/window order. Validate scalar `T_h>0`, finite nonnegative weights, epsilon `1e-6`, canonical classes, and prior vectors in `[0,1]` summing within `1e-6`. Compute `calibrated_logit_c=mean_raw_logit_c/T_h`; `fused_logit_c=calibrated_logit_c+w_filename_h*ln(clamp(filename_prior_c,1e-6,1))+w_dsp_h*ln(clamp(dsp_prior_c,1e-6,1))`; stable softmax subtracts the canonical-order maximum, computes f64 exp, and divides by canonical-order f64 sum. This is the only softmax; no post-softmax calibration. Rust/Python final probabilities must differ <=`1e-7`. Eligibility uses `confidence >= class_threshold` and top1-minus-top2 `margin >= margin_threshold`; equality passes, conflicts abstain before apply. Shared fixtures include each threshold/margin at `-1e-8`, exact, and `+1e-8`, tied logits, extreme logits, and N=1/N=3.
- Prediction records are strict. Playback vector cardinality/order is exactly two `[loop,oneshot]`; instrument exactly ten `[kick,snare,hihat,tom,bass,synth,fx,vocal,percussion,other]`. Every component is finite and in `[0,1]`, vector sum differs from one by at most `1e-6`, and each record includes seal ID, sample ID, content SHA, head, ground truth, mask, final vector, decision, model/policy/preprocessor/evaluator SHAs. Evaluation requires exactly one record for every labeled/unmasked manifest example/head, no duplicate/extra record, no record for masked heads, and `sum_b n_b == N_h`; any violation fails before metrics.
- Sealed-test consumption is machine-enforced and path-nonoverridable against accidental or automated reuse, not a malicious workspace owner. Before hashing, Todo 4 generates random immutable `seal_id`, writes canonical `test-sealed.json` with workspace-relative `consumption_store=tools/auto-tag-model/manifests/consumption/<seal_id>.sqlite`, then writes its raw-byte SHA-256 to fixed `test-sealed.sha256`; no cryptographic signature is claimed. Todo 13's production evaluator accepts no manifest, seal-ID, SHA, ledger, or store path options: it resolves those four fixed workspace files, verifies descriptor SHA before parsing, and rejects absolute paths, `..`, symlinks, or mismatch among descriptor, seal-ID file, and store filename. Before test assets, it writes/fsyncs create-new `<seal_id>.<seal_sha>.consumed`, then inserts one consumed row binding all hashes/prediction path in `BEGIN IMMEDIATE`. Crash burns the seal; marker or row rejects before reads. F4 recomputes from frozen predictions without inference. A new evaluation requires a new group-disjoint seal.
- Status contracts are exhaustive and shared by Rust/Serde/Zod. Per-head is `not_evaluated | eligible | abstained_low_confidence | abstained_low_margin | conflicting_evidence | unsupported_label | insufficient_audio | model_unavailable`; per-axis apply is `not_attempted | applied | unchanged | abstained | protected_manual | protected_legacy`; preview item is `classified | partial | abstained | not_found | missing_file | stale_content | cancelled | failed`; apply item is `applied | partially_applied | unchanged | protected | abstained | not_found | missing_file | stale_content | cancelled | busy_exhausted | failed`. Validation errors have no items. Every item has both head and axis records; preview axes are `not_attempted`; pre-inference operational outcomes use heads `not_evaluated`/axes `not_attempted`; atomic two-head inference cannot cancel between heads. Cancellation observed before opening a transaction yields item `cancelled` and no commit. Cancellation arriving after `BEGIN IMMEDIATE` never overrides reality: finish transaction, return actual derived `applied|partially_applied|unchanged|protected|abstained` with `cancellation_observed_after_commit=true`, then emit later requested IDs as `cancelled` with not-evaluated/not-attempted records. Other operational precedence is `not_found > missing_file > stale_content > busy_exhausted > failed`; success derivation remains as stated.
- Response bounds are identical in Rust and Zod: 1-16 IDs, each integer in `1..=9_007_199_254_740_991`, and duplicate IDs are rejected before any work; maximum three candidates per head; maximum eight reason codes; each reason/code <=96 ASCII bytes; bounded evidence JSON <=2048 bytes per sample; all numbers finite; serialized response <=64 KiB. Raw logits are never returned.
- Preview QA compares all relevant SQLite tables before/after and asserts no UI queue event. Apply QA invokes identical requests twice and expects the second result to be `unchanged`.

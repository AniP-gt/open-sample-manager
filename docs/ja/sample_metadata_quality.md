# サンプルメタデータと品質チェック

Open Sample Manager は、ライセンス情報と品質シグナルを各登録サンプルと並べて保存します。データはローカルの SQLite データベースに残り、ライブラリの書き出しと取り込みにも含まれます。

## ライセンスと出所のメタデータ

各サンプルには次を保存できます。

| フィールド | 用途 |
|---|---|
| 出所 | Splice、ADSR、無料パック、自分の録音など、音の入手元 |
| パック名 | サンプルパック、コレクション、製品の名前 |
| ライセンス | ロイヤリティフリー、商用可、自分の録音、不明などの短いラベル |
| ライセンス URL | ライセンスページ、製品ページ、ダウンロードページへのリンク |
| メモ | 使用上の注意、クレジット表記の規則、購入情報の自由記述 |
| 取り込み日 | 行がローカルライブラリに追加された日付 |

サンプルリストの `LIC` セルをクリックしてこれらのフィールドを編集します。複数のサンプルを選択した場合、同じ値が選択したすべての行に適用されます。空のフィールドは空のメタデータとして保存されます。

サンプルリストにはライセンスフィルターがあり、検索ボックスでは出所、パック名、ライセンステキスト、タグ、ファイル名、品質フラグも確認します。

## 品質チェック

品質チェックはオーディオのスキャンと取り込み中に実行されます。音を DAW に入れる前に、よくある問題を見つけるためのものです。

| フィールド | 意味 |
|---|---|
| Peak dB | 最大絶対サンプルレベルを dB に変換した値 |
| RMS dB | 平均パワーレベルを dB に変換した値 |
| 先頭の無音 | サンプル先頭の無音時間。ミリ秒単位 |
| クリッピング数 | フルスケールに近いサンプルの数 |
| チャンネル数 | デコーダーが報告したソースチャンネル数 |
| ビット深度 | デコーダーが公開する場合のソースビット深度 |
| 品質フラグ | 解析で見つかった問題の短いラベル |

現在のフラグは次のとおりです。

| フラグ | 条件 |
|---|---|
| empty_or_silent | 測定可能な信号がない |
| clipping | 1 個以上のサンプルがフルスケールに近い |
| low_level | Peak が非常に低い |
| very_quiet | RMS レベルが非常に低い |
| leading_silence | サンプルの先頭に 100 ms を超える無音がある |

サンプルリストにはコンパクトな `QC` ステータスが表示されます。`OK` は品質フラグが見つからなかったこと、`!` は 1 個以上のフラグがあることを示します。サンプルリストのツールバーにある `QC` ボタンで、品質フラグ付きのサンプルだけを表示できます。

## 保存に関する注記

フィールドは `samples` テーブルに保存されます。既存のデータベースは起動時に移行されるため、古いライブラリにも手動リセットなしで新しい列が追加されます。

サンプルを再スキャンした場合や、再生または楽器分類を編集した場合も、手動で設定したライセンスメタデータは保持されます。再解析で品質メトリクスは更新されますが、出所、パック、ライセンス、URL、メモのフィールドは上書きされません。

品質メトリクスのレベルチェックには、既存のデコード済み解析バッファーを使います。チャンネル数とビット深度は、利用可能な場合にデコーダーのメタデータから取得します。一部の圧縮形式ではビット深度が公開されないため、このフィールドは空になることがあります。

## 推奨ワークフロー

1. サンプルフォルダーをスキャンします。
2. `QC` を使い、クリッピング、先頭の無音、音量が非常に低いファイルを探します。
3. 行の `LIC` をクリックし、出所、パック、ライセンス、URL、メモを入力します。
4. メタデータを編集する前に関連する複数サンプルを選択し、パック全体に一度にタグを付けます。
5. 書き出しや商用利用の前にライセンスフィルターを使います。

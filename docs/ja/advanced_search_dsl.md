# 高度な検索 DSL

サンプル検索バーでは、小さなクエリ言語を使ってフリーテキスト、メタデータフィルター、除外条件を一つの入力にまとめられます。通常の単語はこれまでどおりファイル名とタグのあいまい一致に使われるため、`kick 808` もそのまま使えます。

## 簡単な例

```text
kick bpm:120-180 type:oneshot tag:metal
guitar key:Am bpm:140-160 type:loop
snare -rimshot favorite:true
instrument:kick tag:drums -tag:processed
```

すべての条件は暗黙の AND で結合されます。サンプルは正の条件をすべて満たし、負の条件には一致しない必要があります。

## 対応する条件

| 条件 | 例 | 意味 |
|---|---|---|
| フリーテキスト | `kick 808` | ファイル名またはタグにあいまい一致 |
| 負のテキスト | `-rimshot` | ファイル名またはタグがその語に一致するサンプルを除外 |
| BPM 範囲 | `bpm:120-180` | 範囲内の BPM を持つサンプルに一致 |
| BPM 完全一致 | `bpm:140` | その BPM 値を持つサンプルに一致 |
| 開いた BPM 範囲 | `bpm:120-` または `bpm:-160` | 境界以上または以下のサンプルに一致 |
| 再生タイプ | `type:loop`、`type:oneshot`、`type:one-shot` | ループまたはワンショットのサンプルに一致 |
| 楽器 | `instrument:kick` | 割り当てられた楽器タイプに一致 |
| キー | `key:C`、`key:C#`、`key:Am` | 検出されたピッチクラスに一致。マイナー接尾辞は受け付けられ、ルートのピッチクラスへ正規化 |
| タグ | `tag:metal` | 割り当てられたサンプルタグに一致 |
| 負のタグ | `-tag:rimshot` | そのタグを持つサンプルを除外 |
| お気に入り | `favorite:true`、`favorite:false` | ローカル UI のお気に入りに一致 |

フィールド名は大文字と小文字を区別しません。`type`、`playback`、`playbackType`、`sampleType` は同じ再生タイプフィルターの別名です。`tag` と `tags` も別名です。

## 引用符付きの値

値にスペースが含まれる場合は二重引用符を使います。

```text
tag:"one shot" bpm:90-120
```

引用符はトークンをまとめるだけで、検索値には含まれません。

## バックエンドと UI の動作

大半の条件はページネーションより前に Rust バックエンドで適用されるため、範囲とメタデータのフィルターによって空のページが作られることはありません。`favorite:true` と `favorite:false` は SQLite のサンプル行ではなくローカル UI 状態に保存されるため、UI で適用されます。

未知のフィールド名は通常のテキスト検索として扱われます。これにより、クエリを入力途中でも検索が役立ち、編集中に失敗しません。

## 現在の対象範囲

DSL は現在、オーディオサンプル検索に適用されます。MIDI 検索は既存の検索ボックスとメタデータコントロールを使います。

# MCP 連携

Open Sample Manager は、MCP ホストをデスクトップアプリで実行中のサンプルライブラリへ接続できます。この連携はローカルの Node.js stdio MCP サーバーであり、ネットワークサービスではありません。

パッケージはプライベートで未公開です。このチェックアウトからビルドしてください。

## 目的と機能

サーバーにより、MCP ホストは登録済みサンプルの検索、サンプルの確認、類似サンプルの検索、結果のアプリへの送信、サンプルのプレビュー、コレクションへのサンプル追加を行えます。データベースの所有権、再生、UI 制御はデスクトップアプリに残ります。

## アーキテクチャ

デスクトップアプリがデータベース、ローカル API、再生、UI コマンドキューを管理します。MCP サーバーは接続マニフェストを読み、検証してから、ベアラー認証付きで `http://127.0.0.1:37421/v1` を呼び出します。SQLite データベース、オーディオファイル、その他のサンプルファイルを直接読み取ることはありません。

アプリは起動のたびに新しいベアラートークンとインスタンス ID を作成します。MCP サーバーは各リクエストの前に、マニフェストの PID がまだ生きているか確認します。`401` の後は、インスタンス ID が変わっていた場合に限り、マニフェストを再読み込みして一度だけ再試行します。

## クイックスタート

1. Node.js `^20.19.0 || >=22.12.0` を入れ、必要に応じてプロジェクトの bootstrap を実行します。
2. MCP パッケージの依存関係を入れ、リポジトリのルートからエントリーポイントをビルドします。

   ```bash
   npm ci --prefix mcp-server
   npm run mcp:build
   ```

3. MCP ホストを開始する前に、デスクトップアプリを起動します。アプリが接続マニフェストを作成して管理します。
4. MCP ホストを開始する環境でマニフェストパスを設定します。

   ```bash
   export OPEN_SAMPLE_MANAGER_CONNECTION_FILE="/absolute/path/to/localhost-api-connection.json"
   ```

   `OPEN_SAMPLE_MANAGER_CONNECTION_FILE` は、アプリが作成した秘密のマニフェストを指します。`OPEN_SAMPLE_MANAGER_MCP_DIR` は、チェックアウトパスをサンプルのホスト設定で使うための補助変数です。

   ```bash
   export OPEN_SAMPLE_MANAGER_MCP_DIR="/absolute/path/to/open-sample-manager/mcp-server"
   ```

5. ホストが `dist/stdio.js` を指定して `node` を実行するよう設定します。正確な設定は、パッケージ README の[Claude Code 設定](../../../mcp-server/README.md#claude-code)と[OpenCode 設定](../../../mcp-server/README.md#opencode)を参照してください。README には現在のアプリマニフェストパスと低レベルの stdio 詳細もあります。

## MCP ホスト設定

MCP エントリーポイントは `mcp-server/dist/stdio.js`、パッケージ bin 名は `open-sample-manager-mcp` です。マニフェストの内容を設定ファイルへコピーせず、`OPEN_SAMPLE_MANAGER_CONNECTION_FILE` でマニフェストパスを設定してください。`OPEN_SAMPLE_MANAGER_MCP_DIR` は任意で、サンプルのホスト設定にチェックアウトパスを渡すだけです。

サーバーは MCP プロトコルメッセージだけを stdout に書きます。診断情報は stderr に出ます。デスクトップアプリは MCP ホストと同じマシン、同じユーザーセッションで実行したままにしてください。

## ツール

すべてのツール入力は JSON オブジェクトです。追加フィールドは拒否されます。

| ツール | 入力 | 動作 |
| --- | --- | --- |
| `search_samples` | 任意の構造化フィルター。`query`、サンプルタイプ、楽器、BPM 範囲、キー、タグ、ディレクトリパス、limit、offset を含む | ローカルの登録済みライブラリを検索します。 |
| `get_sample` | `sample_id` | マスク済みのサンプルレコード一つを返します。 |
| `find_similar_samples` | `sample_id`、`limit`、任意の `exclude_duplicates` | ライブラリサンプルの埋め込みベースの近傍を探します。 |
| `show_samples_in_app` | 順序付きの `sample_ids`、任意の `selected_id` | ID をデスクトップアプリの表示結果セットとしてキューに入れます。`selected_id` を省くと、指定した最初の ID を選択します。 |
| `preview_sample` | `sample_id` | デスクトッププレビュー一つをキューに入れます。 |
| `add_to_collection` | `collection_name`、順序付きの `sample_ids` | 名前付きコレクションをアトミックに作成または再利用し、指定順で ID を追加します。既存の所属は重複しません。 |

### キューに入るデスクトップ操作

`show_samples_in_app` は結果セットを変更しますが、サンプルを再生したりファイルを開いたりしません。`preview_sample` は先頭からちょうど一つのサンプルを選択して再生します。現在の再生を先に停止し、通常の自動再生がオンでもオフでも動作します。

ローカル API はキューへの受け入れ後に HTTP `202 Accepted` を返し、MCP ツール呼び出しは受け入れ済みのレスポンスボディを返します。デスクトップレンダラーは操作を非同期で実行します。レンダラーが利用できない場合、受け入れ済みの表示コマンドとプレビューコマンドは保留のままです。

UI コマンドキューは 64 個のコマンドを保持します。キューがいっぱいの場合、`show_samples_in_app`、`preview_sample`、`add_to_collection` は拒否されます。拒否されたコレクション要求によって、コレクションの変更が書き込まれることはありません。

## 制限と要件

- クエリは 512 文字までです。
- コレクション名と構造化テキストフィルターを含むテキストフィールドは 128 文字までです。
- `sample_ids` は、一意な正のサンプル ID を 1 個から 100 個含む必要があります。`selected_id` を指定する場合、その ID はこの中の一つである必要があります。
- 結果の `limit` 値は 1 から 100、検索の `offset` は 0 から 10000 です。
- 検索が受け付けるタグは最大 100 個で、各タグには 128 文字のテキスト制限があります。
- ローカル API がリクエストボディを受け付ける場合、JSON リクエストボディは 64 KiB に制限されます。
- 結果はローカルの登録済みライブラリから取得されます。サンプルはスキャン済みである必要があり、見つからないファイルやオフラインのファイルはプレビューできません。
- 類似性検索にはソースサンプルの埋め込みが必要です。セマンティックテキスト検索へフォールバックしません。
- コレクションは順序付きサンプル ID の追加だけを行います。この連携では、コレクションの名前変更、削除、直接のデータベースアクセスはサポートしません。

## セキュリティモデル

ローカル API は `http://127.0.0.1:37421/v1` に固定され、ベアラー認証だけを受け付けます。LAN、ブラウザー、CORS、リモートサービスとしては利用できません。Unix では、アプリは所有者だけが読める権限でマニフェストを書き込みます。

接続マニフェストには現在のベアラートークンが含まれるため、秘密として扱ってください。プロンプト、ログ、リポジトリ、シェル履歴、MCP 設定へコピーしてはいけません。`OPEN_SAMPLE_MANAGER_CONNECTION_FILE` を通じてパスだけを設定します。

マニフェスト検証は、変更されたホスト、スキーム、ポート、パス、認証情報、クエリ、フラグメントを拒否します。MCP サーバーはネットワークリスナーを開かず、バックグラウンドサービスも入れません。

## トラブルシューティング

### アプリが起動していない

Open Sample Manager を起動し、起動完了を待ってから再試行します。`OPEN_SAMPLE_MANAGER_CONNECTION_FILE` が、そのアプリインスタンスのマニフェストを指していることを確認してください。マニフェストの PID が停止している場合、ベアラー値を送る前にリクエストが停止します。

### 認証または古いマニフェストのエラー

デスクトップアプリを再起動し、新しいトークンとインスタンス ID を持つ新しいマニフェストを書き出します。マニフェストパスと権限を確認し、問題が残る場合は MCP ホストも再起動します。

### MCP ホストがサーバーを開始できない

リポジトリのルートから `npm ci --prefix mcp-server` と `npm run mcp:build` を実行します。設定した `dist/stdio.js` パスが存在し、`OPEN_SAMPLE_MANAGER_CONNECTION_FILE` がアプリ作成のマニフェストを指していることを確認してください。ホスト設定で `OPEN_SAMPLE_MANAGER_MCP_DIR` を使う場合は、このチェックアウトの `mcp-server` ディレクトリに展開されることを確認します。

### アプリ起動時のポート競合

デスクトップアプリには `127.0.0.1:37421` が必要です。このループバックポートを使っているプロセスを停止してから、アプリをもう一度起動します。MCP クライアントは別のエンドポイントを拒否するため、エンドポイントを変更したり、マニフェストを別の URL に編集したりしないでください。

### 表示またはプレビュー操作が見えない

受け入れ済みのリクエストは、キューへの受け入れだけを示します。保留中のコマンドを処理するため、デスクトップアプリのレンダラーを開いてください。キューがいっぱいの場合は、キューが空くのを待ってから操作を再試行します。

## 開発時のチェック

MCP パッケージを変更した後は、リポジトリのルートから次のコマンドを実行します。

```bash
npm run mcp:typecheck
npm run mcp:test
npm run mcp:build
npm run mcp:ci
```

パッケージの正確なホスト JSON、現在のアプリマニフェストの場所、トランスポートの詳細は、[英語版 MCP サーバー README](../../../mcp-server/README.md)を参照してください。
